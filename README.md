# 论文阅读与知识库

本项目同时承担两项职责：保存论文的最终阅读版本，以及在 Obsidian 中维护可追溯、可增量更新的知识网络。每篇论文都必须按照同一套目录、命名、翻译和验收规则交付；知识笔记则通过稳定标识、带类型关系和来源页码连接不同论文。

项目目录长期只保留：

- 可直接阅读的论文 PDF；
- 全项目统一使用的 `专业术语.md`；
- `知识库/` 中的论文入口、问题、命题、概念、边界和视图；
- `tools/` 中维护中的知识同步工具及其测试；
- 必要的 Obsidian 配置；
- 说明论文清单与项目规范的本文件。

## 目录格式

每篇论文单独使用一个以 arXiv 编号命名的目录，并且论文目录内只保留两份最终 PDF。知识层与 PDF 证据层分开维护：

```text
论文/
├── README.md
├── 专业术语.md
├── <arXiv 编号>/
│   ├── <arXiv 编号>_英文原文.pdf
│   └── <arXiv 编号>_中文译文.pdf
├── 知识库/
│   ├── 00-MOC/
│   ├── 10-论文/
│   ├── 20-问题/
│   ├── 30-命题/
│   ├── 40-概念/
│   ├── 50-边界/
│   ├── 90-视图/
│   ├── 模板/
│   └── .meta/
├── tools/
└── tests/
```

例如：

```text
2203.15556/
├── 2203.15556_英文原文.pdf
└── 2203.15556_中文译文.pdf
```

目录名和文件名均不包含版本号或修订号。文件名始终表示当前正式版本，原文版本只记录在“当前论文”表等元数据中。两份 PDF 必须基于同一个论文版本，不能混用不同来源版本；升级原文或修订译文时，直接替换固定名称的文件，并同步更新元数据。

## 知识层规则

- 一篇论文只对应一个 `paper` 笔记，文件名固定为 `论文 - <arXiv 编号>.md`；英文原文和中文译文是同一来源的两种阅读载体。
- `question` 表示跨论文共同回答的问题，`claim` 表示可被支持、修正或质疑的完整命题，`concept` 只用于会被多篇论文复用的概念，`boundary` 记录适用范围和外推限制。
- 笔记使用稳定的 `uid`，关系只从 `depends_on`、`supports`、`refines`、`challenges`、`limited_by` 等约定字段中选择；关系必须同时在正文中用自然语言说明。
- 每条关键命题都应链接到来源 PDF 的具体页码。自动生成的候选内容必须标记 `review_status: pending`，审核前不视为正式知识。
- 自动同步只能改写明确的 `AUTO` 区块和程序拥有的元数据；`AUTO` 标记之外均为人工内容，任何同步都不得覆盖。
- MOC 负责阅读路径，Canvas 负责带标签的论证图，Bases 负责筛选和维护状态，Graph 只用于观察邻域和发现孤立节点。

## 自动适配新增论文

新增论文时，先按上面的固定命名放齐英文原文和中文译文。同步器会以 arXiv 编号作为稳定标识，计算来源哈希，创建或更新对应的 `paper` 笔记，并重建“待审核论文”和“自动论文总览”。首次纳入或 PDF 内容发生变化时，语义状态会变为 `pending`；已有人工审核内容和人工专题 Canvas 不会被覆盖。

```bash
# 只读检查；有待同步内容时退出码为 1
python3 tools/knowledge_sync.py check --root .

# 先预览，再确认落盘
python3 tools/knowledge_sync.py sync --root .
python3 tools/knowledge_sync.py sync --root . --write

# 在当前终端持续监听；进程停止后监听也会停止
python3 tools/knowledge_sync.py watch --root . --write --interval 10
```

来源同步默认不调用模型。若要为待审核论文生成关系与证据候选，必须显式执行下面的命令；候选仍保持 `pending`，须按 `知识库/模板/语义审核清单.md` 人工核验后才能转为正式知识。

```bash
python3 tools/knowledge_sync.py enrich --root . --run

# 监听到新 PDF 后同时调用 Codex 生成候选；会产生模型用量
python3 tools/knowledge_sync.py watch --root . --write --enrich
```

完整命令和程序拥有范围见 `tools/README.md`。

## 两份 PDF 的定义

### 1. 英文原文

- 使用选定 arXiv 版本的原始论文 PDF。
- 不修改正文、页序、图表或公式。
- 文件名固定为 `<arXiv 编号>_英文原文.pdf`。

### 2. 中文译文

- 面向连续阅读，以中文为主，不附带逐句英文正文。
- 按章节和语义连续排版，不按英文原文页码强制切页，不显示“原文第 N 页”等制作标记。
- 章节、正文、脚注、图表、公式和参考文献必须完整，不得因排版而省略内容。
- 论文原图必须实际嵌入；“图中文字对照”或文字说明不能代替图形主体。
- 展示公式使用原生矢量数学排版，不使用公式截图或带底色的公式图片；公式内的自然语言翻译为中文。
- 应包含清晰的标题页、目录、PDF 书签和可用的内部跳转；原文提供的外部链接应保持可点击。
- 正文中的文献引用必须可点击并跳到对应参考文献；章节、图、表和公式引用必须跳到对应对象。
- 专业术语严格遵守根目录的 `专业术语.md`。
- 文件名固定为 `<arXiv 编号>_中文译文.pdf`。

## 专业术语规则

- `专业术语.md` 是全项目唯一的术语规则来源，不为单篇论文另建私有术语表。
- 表内每个术语只有“英文”或“中文”一种已确认策略，正文统一使用对应写法，不临时改成中英并列。
- 新增或修改术语时，先在 `专业术语.md` 中确认，再应用到相关论文。
- 模型名、数据集名、基准名、缩写、单位和公式变量默认保留原文。
- 必须按语义判断词义；不得对公式、参考文献、模型名或普通同形词做机械替换。

## 统一排版规则

- 英文原文保留发布版本的原始页面尺寸和版式，不为追求统一外观而擅自缩放。
- 新制作的中文译文默认使用 A4；确需沿用原论文版式时可以保留原始页面尺寸，但不得牺牲内容完整性和可读性。
- 中文正文使用 `Songti SC`，标题和表头使用 `Heiti SC`。
- 中文字体必须嵌入 PDF；行内数学可使用支持完整数学符号的字体。
- 两篇论文可以因图表、公式和内容密度采用不同分页，但字体层级、颜色语义和文件命名必须一致。
- 中文译文以纵向 A4 为主；宽表优先通过合理列宽、自动换行、重复表头和跨页长表解决，不因单张表随意混入横向页面。
- 图形与其图注、字段标题与其首段内容不得被不合理地拆到不同页面。
- 外部链接的句末标点必须放在链接目标之外；验收时应检查实际 URI，而不只检查页面上显示的文字。
- 不得出现乱码、缺字方框、原始 LaTeX 控制符、内部引用标签、裁切、重叠或空白页。

## 每篇论文的执行流程

1. 确认 arXiv 编号、选定版本和英文原文页数。
2. 创建 `<arXiv 编号>/` 目录，并按固定名称放入英文原文。
3. 提取需要统一的专业术语；如需新增策略，先更新 `专业术语.md`。
4. 完成中文译文，检查章节、图表、公式、脚注和参考文献覆盖是否完整。
5. 完成内容、术语、字体、结构和视觉验收。
6. 只把两份最终 PDF 留在论文目录，并更新“当前论文”表。
7. 运行知识同步检查；只有英文原文和中文译文齐全且可识别的目录才进入知识层。
8. 审核新增或失效的命题、概念、关系和证据页码，再把 `review_status` 改为 `reviewed`。

## 交付验收清单

每篇论文必须同时满足以下条件：

- [ ] 论文目录名等于 arXiv 编号。
- [ ] 目录内恰好有两份 PDF，名称符合固定规则，并且两份文件基于同一个原文版本。
- [ ] 两份 PDF 都能严格解析，无加密、无空白页。
- [ ] 英文原文与选定 arXiv 版本一致。
- [ ] 中文译文没有遗漏章节、正文、图表、公式、脚注或参考文献。
- [ ] 中文译文采用连续阅读版式，图形与图注、字段标题与内容没有不合理分页。
- [ ] 展示公式为原生矢量排版，公式内自然语言使用对应版本的语言。
- [ ] 术语与 `专业术语.md` 一致，没有同一术语多种写法。
- [ ] 中文正文、标题和数学符号字体正确且已嵌入。
- [ ] 目录、书签、内部跳转和外部链接均可用，外链目标不包含句末标点。
- [ ] 先从英文原文统计文献引用及章节、图、表、公式引用的目标与出现次数，再逐项验证译文覆盖率为 100%；不能只检查“已有链接是否失效”。
- [ ] 每条正文文献引用都能跳到唯一的对应参考文献，所有内部链接目标均存在且跳转位置正确。
- [ ] PDF 中没有缺字、乱码、源码残留、裁切或重叠。
- [ ] 所有页面均完成渲染检查，重点复核首页、图表、公式、附录和末页。
- [ ] README 的论文清单、版本与页数已经更新。
- [ ] 对应的 `paper` 笔记存在且英文原文、中文译文均已登记。
- [ ] 关键命题具有来源页码，新增语义关系已完成审核，不存在误合并的概念节点。
- [ ] 知识同步状态中的文件哈希与当前 PDF 一致。

## 项目中不保留的内容

以下内容不属于最终阅读资料，不得长期放在项目根目录或论文目录中：

- 一次性处理代码；正式维护的 `tools/` 自动同步工具除外；
- 构建缓存、依赖目录和临时文件；
- 逐页截图、联系表和 QA 中间产物；
- 历史副本、旧版 PDF 和压缩归档；
- `.DS_Store`、机器专属会话状态和其他无关本地环境文件；项目约定的 `.obsidian` 配置除外。

确需保留的历史资料应放在项目目录之外的独立备份位置。

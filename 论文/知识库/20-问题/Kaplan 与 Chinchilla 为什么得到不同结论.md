# Kaplan 与 Chinchilla 为什么得到不同结论？

## 先纠正一个常见误读

两篇论文并非一个说“应 early stop”、另一个说“应训练到收敛”。Hoffmann 明确同意计算最优的大模型不应被训练到它能达到的最低损失。真正的分歧是：计算预算增加时，训练 token 数应增长得多快。

## 事实层：实验设计不同

1. **训练时长与学习率调度。** Hoffmann 指出，Kaplan 对不同模型使用固定训练 token 数和固定调度，并利用训练过程中的中间点；若余弦调度远长于当前训练长度，中间损失会高估短训练配置的损失，从而低估更多数据/更长训练的价值。
2. **模型规模区间。** Hoffmann 的分析包含最高 16B 参数模型，且多数模型超过 500M；Kaplan 的运行更多集中在较小规模。Hoffmann 观察到 FLOP-损失前沿存在轻微曲率，说明从小模型做直线外推会改变最优 $N$ 的预测。
3. **估计方式。** Kaplan 组合 $L(N,D)$、$L(N,S_{min})$ 与 critical batch size 关系推导前沿；Hoffmann 额外使用固定计算预算下直接扫描模型规模的 IsoFLOP 剖面，并用三种方法交叉验证。

## 推断层：为什么会得到新比例

当每次训练的学习率调度与目标 token 数匹配，并在多个固定 FLOP 预算下直接观察损失谷底时，“较小模型读更多 token”的配置不再因调度失配而显得过差。更宽的规模区间和前沿曲率又进一步降低了外推得到的最优模型规模。因此 $N,D$ 的指数从约 $0.73/0.27$ 被重新估计为接近 $0.5/0.5$。

这是根据论文方法与结果作出的因果解释；它不能证明所有差异都只由学习率调度造成。
